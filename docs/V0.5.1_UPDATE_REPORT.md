## 一、版本概述

本轮开发（v0.5.1）聚焦于解决实际使用中的**交互卡点、模型切换报错、推理力度静默失效**等关键痛点，并引入了目前主流高级 Agent 必备的**「AI 遇到分歧/方案时向用户主动弹出 ABCD 选择卡片」**的交互决策能力。

## 二、四大核心 Bug 修复详解

### 1. 自定义模型切换时报错且配置丢失（严重 Bug）
- **问题现象**：用户在设置中配置了自定义 OpenAI 兼容接口（如 DeepSeek 或中转站）并添加了模型，但在底栏模型下拉菜单中切换模型时，界面弹出红色报错，且导致原本保存的 Base URL 丢失。
- **源码根因**：
  1. `renderer/modules/menus.js` 切换模型时调用 `setModelConfig`，只传了 `{ provider, model }`，漏传了已有的 `baseUrl`；
  2. `src/electron/services/model-policy-service.ts` 的 `setModelConfig` 未对缺省的 `baseUrl`、`apiKey`、`maxTokens` 做继承合并，直接以 `undefined` 重新初始化 Provider，触发 `OpenAICompatibleProvider` 的必填校验报错，并将 `config.json` 中的 `baseUrl` 覆盖写成 `undefined`。
- **修复方案**：
  - 在 `model-policy-service.ts` 中加入配置继承机制：切换模型时如果未传 `baseUrl` 或 `apiKey`，自动继承原有配置，禁止清空；
  - `menus.js` 切换模型时自动携带当前有效的 `baseUrl`；
  - 修正了下拉菜单中当前激活模型 checkmark 的高亮比对逻辑（从比对 `models[0]` 改为比对当前活跃 `model`）。

### 2. 设置页“返回工作区”按钮极难点击（点击判定缺陷）
- **问题现象**：在全屏设置页面中，左上角的 `‹ 返回工作区` 按钮点击经常毫无反应，必须精准找角度或反复选取文本后才能勉强点中。
- **源码根因**：
  - 窗口顶栏 `#topbar` 高度为 `48px`，设置了 `-webkit-app-region: drag;`（操作系统窗口拖动区域）；
  - 全屏设置层覆盖了窗口顶部，但其导航栏 `.set-nav` 和返回按钮 `.set-back` 刚好坐落在顶部 `y = 22px ~ 47px` 范围内，且**没有设置 `-webkit-app-region: no-drag`**；
  - 操作系统窗口管理器把鼠标按下事件优先识别成了“试图拖拽窗口”，从而截断并吞掉了网页原生的 `click` 事件。
- **修复方案**：
  - 在 `renderer/style.css` 中为 `#settings-view`、`.set-nav` 和 `.set-back` 显式设置 `-webkit-app-region: no-drag !important;`；
  - 将 `.set-back` 的内边距从 `6px 10px` 扩大到 `10px 14px`，扩展可点击热区，并增加平滑 Hover 动效。

### 3. 模型推理强度无法真实生效（静默拦截修复）
- **问题现象**：用户在界面下拉菜单中选择了“低 / 中 / 高”推理力度，但调用 DeepSeek-R1 或 OpenAI o1/o3 模型时，后台并没有真正将思维链参数传给模型。
- **源码根因**：
  - `src/providers/openai-compatible.ts` 中设置了 `if (chatOptions?.reasoningEffort && this.opts.enableReasoningEffort)`，而 `registry.ts` 中 `enableReasoningEffort` 默认被写死为 `false`，且界面无处开启；
  - 导致用户在界面设置的推理力度被底层直接丢弃。
- **修复方案**：
  - 在 `src/providers/registry.ts` 中让 DeepSeek 及已配置端点默认开启 `enableReasoningEffort`；
  - 在应用层配置 `config.json` 中统一放行，同时保留严格兼容网关的逃生门；
  - 清理了前端界面中具有误导性的“请手动修改 config.json”的 Toast 提示。

### 4. 没有一键拉取模型列表功能
- **问题现象**：用户配置好中转站或本地大模型后，必须手动逐个输入模型名字并点击添加，费时费力。
- **解决方案**：见下方第四节。

## 三、核心新功能：AI 决策 ABCD 交互选择弹窗系统

### 1. 设计理念
当 AI 遇到以下场景时，不再黑盒自行猜测或输出大段文字等待：
- 存在多种可选的技术方案（如方案 A vs 方案 B）；
- 关键重构或破坏性操作前的决策确认；
- 需求不明确或存在技术路线分歧。

AI 会主动调用内置交互决策工具，在界面中央弹出一张与软件完全同构的**原生液态玻璃决策卡片**。

### 2. 核心组成
1. **内置插件**：`plugins/builtin/ask-user/`
   - `manifest.json`：声明插件元数据，零外部权限依赖；
   - `index.js`：提供工具 `ask-user.choose`，声明 `requiresApproval: true`。
   - 工具入参：
     - `question`：决策的核心问题；
     - `description`：背景上下文与权衡分析；
     - `rationale`：AI 推荐的最佳理由；
     - `options`：A / B / C / D 选项数组（含标题、说明、推荐标记 `recommended: true`）。
2. **原生液态玻璃弹窗（`#choice-modal`）**：
   - 采用多层高斯模糊与半透明毛玻璃材质；
   - 选项卡片网格布局，AI 推荐项自动高亮显示紫色/淡蓝发光边框，并打上 `★ AI 推荐` 徽章；
   - 选项左侧带有醒目的 `A` / `B` / `C` / `D` 单选徽章；
   - 底部提供补充输入框，支持用户输入额外自定义调整意见。
3. **极速键盘交互支持**：
   - 键盘按下 `A` / `B` / `C` / `D` 或 `1` / `2` / `3` / `4` 直接高亮切换选项；
   - 按 `Enter` 直接确认提交；双击选项卡片也可秒速确认；
   - 按 `Escape` 或点击跳过可直接取消决策。
4. **决策结果回填**：
   - 用户做出的选项与补充意见通过工具结果直接回喂给 `core/loop.ts` 的 Agent 循环；
   - AI 立即根据用户选定的路线继续编写代码并向下推进。

## 四、一键拉取远程模型列表功能

1. **后端 IPC 接口**：`fetch-models`
   - 实现于 `src/electron/services/model-policy-service.ts`，暴露于 `main.ts` 与 `preload.ts`；
   - 自动向当前或指定的 Provider 请求标准 `/v1/models` 端点；
   - 自动解析返回的模型列表，过滤空项、去重并按字母排序返回。
   - 针对 Anthropic 供应商，内置返回常用的官方 Claude 模型清单。
2. **前端界面集成**：
   - 在全屏设置页的模型添加输入框右侧，新增 **`[ ⚡ 一键拉取远程模型 ]`** 按钮；
   - 点击后按钮显示加载态并自动向端点查询，查询完毕后将端点支持的全部模型批量生成芯片标签，保存即可直接使用。
